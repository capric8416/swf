### 步骤 5：自动设计接口规范

#### 5.1 RESTful API 设计规范

**URL设计规范：**

| 规则 | 说明 | 示例 |
|------|------|------|
| 小写字母 | 统一使用小写 | `/api/v1/users` |
| 复数名词 | 资源使用复数形式 | `/users` 而非 `/user` |
| 层级关系 | 用路径表示关联 | `/users/{id}/orders` |
| 避免动词 | 用HTTP方法表示操作 | `GET /users` 而非 `/getUsers` |
| 过滤排序 | 用查询参数 | `/users?status=active&sort=-created_at` |
| 版本控制 | URL中包含版本 | `/api/v1/...` |

**HTTP方法使用规范：**

| 方法 | 用途 | 幂等性 | 示例 |
|------|------|--------|------|
| GET | 获取资源 | 幂等 | `GET /users/{id}` |
| POST | 创建资源 | 非幂等 | `POST /users` |
| PUT | 全量更新 | 幂等 | `PUT /users/{id}` |
| PATCH | 部分更新 | 非幂等 | `PATCH /users/{id}` |
| DELETE | 删除资源 | 幂等 | `DELETE /users/{id}` |

**状态码使用规范：**

| 状态码 | 使用场景 | 说明 |
|--------|----------|------|
| 200 OK | 成功响应 | 标准成功 |
| 201 Created | 创建成功 | 返回新资源 |
| 204 No Content | 删除成功 | 无返回体 |
| 400 Bad Request | 请求参数错误 | 客户端错误 |
| 401 Unauthorized | 未认证 | 需要登录 |
| 403 Forbidden | 无权限 | 权限不足 |
| 404 Not Found | 资源不存在 | 路径或资源不存在 |
| 409 Conflict | 资源冲突 | 重复创建等 |
| 422 Unprocessable | 业务逻辑错误 | 验证失败 |
| 429 Too Many Requests | 限流 | 请求过于频繁 |
| 500 Internal Error | 服务器错误 | 服务端异常 |

#### 5.3 GraphQL 设计规范（如适用）

**Schema设计原则：**
- 使用名词命名类型（User, Order）
- Query用于查询，Mutation用于修改
- 使用Input类型作为参数
- 实现分页使用Connection规范

**示例：**

```graphql
type Query {
  user(id: ID!): User
  users(first: Int, after: String): UserConnection
}

type Mutation {
  createUser(input: CreateUserInput!): CreateUserPayload
}
```

### 步骤 6：自动设计认证授权方案

基于安全等级自动推荐认证方案：

| 安全等级 | 推荐方案 | 说明 |
|----------|----------|------|
| 公开 | 无认证/API Key | 简单场景 |
| 内部 | JWT | 有状态认证 |
| 敏感 | JWT + RBAC | 认证+授权 |
| 机密 | OAuth2/OIDC | 第三方认证集成 |

**JWT认证规范：**

| 组件 | 说明 |
|------|------|
| Token类型 | Access Token + Refresh Token |
| 签名算法 | RS256（推荐）或 HS256 |
| Access Token有效期 | 15分钟 - 2小时 |
| Refresh Token有效期 | 7天 - 30天 |
| Token传输 | HTTP Header: `Authorization: Bearer {token}` |

**权限控制模型选择：**

| 模型 | 适用场景 | 说明 |
|------|----------|------|
| RBAC | 角色明确的系统 | 基于角色的访问控制 |
| ABAC | 复杂权限场景 | 基于属性的访问控制 |
| ACL | 资源级权限 | 访问控制列表 |

**业务规则：**
1. 用户名全局唯一，注册后不可修改
2. 邮箱必须验证通过后才能登录
3. 密码需要加密存储（bcrypt）

- 响应时间：< 200ms（P95）
- 并发限制：100 次/秒

## 设计原则

1. **统一规范**：全系统遵循一致的接口设计规范
2. **版本兼容**：API变更保持向后兼容
3. **安全优先**：认证授权覆盖所有敏感接口
4. **性能考量**：根据场景选择最优通信方式
5. **可观测性**：接口调用可追踪、可监控
6. **文档驱动**：接口即文档，保持同步更新
