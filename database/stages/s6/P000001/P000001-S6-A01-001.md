### 2.2 功能分解

#### F-001：全局 Token 使用趋势看板

**功能描述**：
展示全中心 Token 使用量随时间变化的趋势，支持按日/周/月维度查看。

**输入**：
- 时间范围（开始日期、结束日期）
- 统计维度（日/周/月）
- 平台筛选（可选：Trae/阿里/其他）

**处理逻辑**：
1. 从缓存查询聚合数据，未命中则查询数据库
2. 按时间维度聚合 Token 使用量
3. 计算环比和同比数据
4. 返回趋势数据点

**输出**：
```json
{
  "period": "daily",
  "data_points": [
    {
      "date": "2026-03-27",
      "token_count": 150000,
      "api_calls": 3500,
      "mom_change": 0.15,
      "yoy_change": null
    }
  ],
  "summary": {
    "total_tokens": 4500000,
    "total_calls": 105000,
    "avg_daily_tokens": 150000
  }
}
```

**界面元素**：
- 折线图（Token 趋势）
- 柱状图（API 调用次数）
- 数据卡片（总计、日均、环比）

**性能要求**：
- 响应时间 < 500ms（缓存命中）
- 响应时间 < 2s（数据库查询）
- 缓存 TTL：1 小时

### 2.4 数据库操作

#### 查询 Token 趋势数据

```sql
-- 日级别 Token 使用趋势
SELECT 
    usage_date,
    SUM(token_count) as total_tokens,
    SUM(api_calls) as total_calls,
    COUNT(DISTINCT user_id) as active_users
FROM token_usage
WHERE usage_date BETWEEN :start_date AND :end_date
  AND (:platform IS NULL OR platform = :platform)
GROUP BY usage_date
ORDER BY usage_date;
```

### 6.3 Token 刷新机制

#### 双 Token 机制

- **Access Token**: 有效期 1 小时，用于 API 请求
- **Refresh Token**: 有效期 7 天，用于刷新 Access Token

#### 刷新时机

- Access Token 过期前 5 分钟自动刷新
- 前端拦截 401 错误，自动调用刷新接口

#### 刷新流程

```
前端发起请求 → Access Token 过期 → 返回 401
→ 前端调用 /auth/refresh 接口（携带 Refresh Token）
→ 后端验证 Refresh Token → 返回新 Access Token + 新 Refresh Token
→ 前端重试原请求
```

#### 安全控制

- Refresh Token 一次性使用（刷新后作废，生成新的）
- Refresh Token 绑定设备指纹
- 异常刷新行为检测（频繁刷新、异地刷新）

#### API 接口

```
POST /api/v1/auth/refresh
请求：{ "refresh_token": "xxx" }
响应：{ 
  "access_token": "xxx", 
  "refresh_token": "xxx", 
  "expires_in": 3600 
}
```

#### TTL 计算示例

```python
def get_cache_ttl(data_type: str) -> int:
    """获取缓存 TTL（秒）"""
    ttl_map = {
        'global_stats': 3600,      # 1 小时
        'project_stats': 1800,     # 30 分钟
        'personal_stats': 900,     # 15 分钟
        'config': 86400,           # 24 小时
        'permissions': 3600,       # 1 小时
        'session': 7200,           # 2 小时
        'not_found': 300           # 5 分钟（缓存穿透）
    }
    # 添加随机值防止缓存雪崩
    base_ttl = ttl_map.get(data_type, 1800)
    jitter = random.randint(-300, 300)  # ±5 分钟
    return max(60, base_ttl + jitter)
```

#### Cache-Aside 模式

```python
async def get_project_stats(project_id: int) -> dict:
    cache_key = f"stats:project:{project_id}:overview"
    
    # 1. 尝试从缓存读取
    cached = await redis.get(cache_key)
    if cached:
        return cached
    
    # 2. 缓存未命中，从数据库读取
    stats = await db.get_project_stats(project_id)
    
    # 3. 写入缓存

    return stats
```

### 10.4 缓存异常处理

#### 缓存穿透防护

**问题**：查询不存在的数据，请求直接打到数据库

**解决方案**：
- 空值也缓存（TTL=5 分钟）
- 布隆过滤器预判

```python
async def get_data_with_cache(key: str):
    # 尝试从缓存读取
    cached = await redis.get(key)
    if cached is not None:
        return cached if cached != '__NOT_FOUND__' else None
    
    # 从数据库读取
    data = await db.get(key)
    
    if data is None:
        # 空值缓存，防止缓存穿透
        await redis.setex(key, 300, '__NOT_FOUND__')
        return None
    
    # 正常缓存
    await redis.setex(key, get_cache_ttl('default'), data)
    return data
```

#### 缓存雪崩防护

**问题**：大量缓存同时过期，请求集中到数据库

**解决方案**：
- TTL 增加随机值（±5 分钟）
- 热点数据永不过期

#### 缓存击穿防护

**问题**：热点 key 过期，大量请求集中访问

**解决方案**：
- 互斥锁（分布式锁）
- 逻辑过期（后台异步更新）

```python
async def get_hot_data(key: str):
    cached = await redis.get(key)
    if cached:
        return cached
    
    # 获取分布式锁
    lock = await redis.lock(f"lock:{key}", timeout=10)
    if await lock.acquire():
        try:
            # 双重检查
            cached = await redis.get(key)
            if cached:
                return cached
            
            # 从数据库加载
            data = await db.get(key)
            await redis.setex(key, get_cache_ttl('hot'), data)
            return data
        finally:
            await lock.release()
    else:
        # 等待锁释放后重试
        await asyncio.sleep(0.1)
        return await get_hot_data(key)
```
