## 阶段概述

本阶段基于需求分析产物，**自动推导**软件架构设计方案。当需求不明确或存在多个可行方案时，通过**用户交互**确认关键决策。

### 设计哲学

- **自动推导为主**：基于需求特征自动分析，减少用户负担
- **用户确认为辅**：仅在必要时请求用户确认
- **提供理由**：每个推荐都附带理由，帮助用户理解决策
- **记录决策**：所有决策（自动或人工）都记录理由

## 自动推导规则

### 系统特征识别

| 分析维度 | 识别依据 | 输出 |
|----------|----------|------|
| **系统类型** | 用户故事、功能描述 | Web/移动/桌面/嵌入式/大数据 |
| **用户规模** | 用户数量、并发需求 | 内部/部门级/企业级/互联网级 |
| **数据特征** | 数据实体、数据关系 | 关系型/文档型/时序型/混合型 |
| **性能要求** | 响应时间、吞吐量 | 低/中/高/极高 |
| **集成需求** | 外部系统引用 | 简单/中等/复杂 |
| **安全等级** | 敏感数据处理 | 公开/内部/敏感/机密 |

### 架构风格推导

| 系统特征组合 | 推荐架构风格 | 理由 |
|--------------|--------------|------|
| 企业Web + 中等规模 + 关系数据 | 分层架构 | 结构清晰，易于维护 |
| 互联网应用 + 高并发 + 高可用 | 微服务架构 | 水平扩展，独立部署 |
| 实时处理 + 流式数据 + 高吞吐 | 事件驱动架构 | 异步处理，削峰填谷 |
| 复杂业务 + 领域模型 + 长期演进 | 领域驱动设计 | 业务对齐，易于演进 |
| 多端应用 + 统一后端 | 前后端分离 + BFF | 适配多端，统一接口 |

### 技术方案推导

| 性能等级 | 推荐策略 |
|----------|----------|
| 低（<100并发） | 单体应用，简单缓存 |
| 中（100-1000并发） | 应用集群，数据库优化 |
| 高（1000-10000并发） | 分布式缓存，读写分离，消息队列 |
| 极高（>10000并发） | 微服务，分库分表，CQRS |

| 数据特征 | 推荐存储 |
|----------|----------|
| 关系型数据为主 | PostgreSQL / MySQL |
| 文档型数据为主 | MongoDB |
| 海量时序数据 | TimescaleDB / InfluxDB |
| 复杂关系查询 | Neo4j |
| 混合数据类型 | 多存储组合 |

## 用户交互场景

### 场景 1：提供选项

当存在多个同等可行的方案时，提供选项供用户选择：

```
基于需求分析，系统具有以下特征：
- 系统类型：企业Web应用
- 用户规模：部门级（约500用户）
- 性能要求：中等并发（约200并发）

推荐架构方案：
A. 分层架构 + 单体部署（推荐）
   - 适合当前规模，开发效率高
   - 未来可平滑演进为微服务
   
B. 微服务架构 + 容器部署
   - 适合未来扩展，但初期复杂度高
   - 需要DevOps能力支持

请选择架构方案（A/B）：
```

### 场景 2：询问澄清

当需求描述不明确时，询问用户澄清：

```
需求中提到"系统需要支持高可用"，但未明确可用性指标。

常见可用性等级：
- 99.9%（年停机时间 < 8.76小时）- 一般业务系统
- 99.99%（年停机时间 < 52.6分钟）- 重要业务系统
- 99.999%（年停机时间 < 5.26分钟）- 核心业务系统

请确认系统的可用性要求：_____
```

### 场景 3：确认假设

基于分析做出假设，请求用户确认：

```
基于需求分析，做出以下假设：

假设 1：系统主要面向内部用户，不需要考虑CDN加速
假设 2：数据增长率为每月10%，3年内数据量在可管理范围
假设 3：系统集成主要通过REST API，不需要消息队列

请确认以上假设是否成立（是/否）：
如有不成立的假设，请说明：_____
```

## 执行流程

### 标准流程

```
开始
  ↓
读取需求分析产物
  ↓
S5-A01: 自动分析特征 → 推导架构方向 → 交互确认 → 生成架构愿景
  ↓
S5-A02: 基于愿景 → 选择视图 → 生成架构视图
  ↓
S5-A03: 分析数据需求 → 推荐存储 → 生成数据架构
  ↓
S5-A04: 识别集成点 → 设计接口 → 生成接口架构
  ↓
S5-A05: 分析部署约束 → 推荐方案 → 生成部署架构
  ↓
S5-A06: 检查完整性 → 识别风险 → 生成分评审报告
  ↓
结束
```

### 轻量流程

```
开始
  ↓
读取需求分析产物
  ↓
S5-A01: 架构愿景定义（核心决策）
  ↓
S5-A02: 架构视图设计（逻辑视图 + 场景视图）
  ↓
S5-A03: 数据架构设计（核心数据模型）
  ↓
结束（进入实现阶段）
```

## 注意事项

1. **自动推导为主**：优先基于需求自动推导，减少用户负担
2. **提供理由**：每个推荐都应附带理由，帮助用户理解
3. **保持开放**：用户可以选择不同于推荐的方案
4. **记录决策**：所有决策（自动或人工）都应记录理由
5. **迭代优化**：根据用户反馈持续优化推导规则
6. **不依赖配置**：不通过配置文件，而是通过需求分析自动推导
