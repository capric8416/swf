### 步骤 3：自动推导部署模式

基于系统特征自动推荐部署模式：

**部署模式选择矩阵：**

| 系统特征 | 推荐部署模式 | 理由 |
|----------|--------------|------|
| 小型应用 + 单机部署 | Docker Compose | 运维简单，资源占用低 |
| 中型应用 + 高可用要求 | Kubernetes (托管) | 自动恢复，水平扩展 |
| 大型应用 + 多云部署 | Kubernetes (多云) | 避免厂商锁定 |
| 无服务器 + 事件驱动 | FaaS (Lambda/Cloud Functions) | 按需付费，自动扩缩 |
| 传统应用 + 渐进迁移 | 虚拟机 + 容器混合 | 渐进式现代化 |
| 边缘计算 + 低延迟 | 边缘节点部署 | 靠近用户，降低延迟 |

**云服务选型矩阵：**

| 场景 | 推荐方案 | 适用云服务商 |
|------|----------|--------------|
| 全托管 + 快速上线 | PaaS (App Engine/Elastic Beanstalk) | AWS, Azure, GCP, 阿里云 |
| 容器化 + 简单编排 | 托管K8s (EKS/AKS/GKE) | AWS, Azure, GCP |
| 无服务器 | Lambda + API Gateway | AWS, 阿里云函数计算 |
| 国内部署 + 合规 | 阿里云/腾讯云/华为云 | 国内云服务商 |
| 混合云 | 私有云 + 公有云 | VMware + 公有云 |

## 设计原则

1. **基础设施即代码**：所有基础设施配置通过代码管理，可版本控制、可复现
2. **不可变基础设施**：部署单元（容器/镜像）不可变，配置外部化
3. **声明式管理**：描述期望状态，由系统确保实际状态与期望一致
4. **自动化优先**：部署、测试、监控尽可能自动化，减少人工干预
5. **安全内建**：安全策略融入部署流程，而非事后添加
6. **可观测性**：系统具备完善的监控、日志、追踪能力
7. **弹性设计**：支持自动扩缩容，具备故障自愈能力
